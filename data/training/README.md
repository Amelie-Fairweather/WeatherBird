# Vermont Snow Day Training Pipeline

Labeled cases live in `vt-snow-day-cases.json` (VT-SND-001…020).  
Flat ML feature rows are regenerated by the eval harness into `vt-snow-day-features.csv`.

## Evaluate / calibrate

```bash
npm run train:snow-day
```

Target: **100% category accuracy** on the labeled set (Closed / Delayed Start / Open).

Calibration code: `lib/training/snowDayCalibration.ts`  
Live wiring: `lib/snowDayPredictionService.ts` (70/30 VTrans blend + training multinomial)

## Baselines learned from labels

| Parameter | Value |
|---|---|
| Full close snow | 6" |
| Delay snow | 3" |
| Ice | 0.25" |
| Extreme cold | 10°F |
| High wind | 30 mph |
| VTrans / weather blend | 70% / 30% |
| Hazard floor | ≥ 70 → close |
| Clear corridor cap | ≤ 42% close (unless ice/snow/arctic cold) |
| Bus-stop wind chill override | ≤ −25°F closes even if pavement clear |

## Recommended next steps (expand beyond these 20)

1. **Historical baselines** — pull GHCN daily climate for BTV, Rutland, St. Johnsbury, Bennington (snowfall, Tmin, weather codes).
2. **Pair with real closures** — supervisory-union closure announcements ↔ weather/RWIS features for true targets.
3. **Grow to thousands of rows** — 50+ districts × multiple winters; keep CSV/Parquet schema stable (`snowfall_in,temp_f,wind_mph,ice_in,mu_friction,is_commute_window,target_closed`).
4. **Tabular model** — once ≥ ~2–5k labeled rows, train XGBoost/LightGBM on the flat features and compare against the rule calibrator on a held-out winter.
